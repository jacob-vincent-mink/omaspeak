# NVIDIA GB10 CUDA Plugin EP validation — 2026-09-15

Omaspeak commit `e634c3c547e9c8bd62ebe3ae61e458679fedbeec` was
archived into a clean aarch64 build tree on an NVIDIA GB10 host. Checksums of
`Cargo.toml`, `Cargo.lock`, `src/supertonic.rs`, and
`src/runtime_inventory.rs` matched the local tree before the release build.
All synthesis wrote WAV files directly; no audio was played.

The host ran Linux 6.17.0-1032-nvidia with NVIDIA driver 580.173.02. The test
used the official ONNX Runtime 1.30.0 aarch64 CPU core and Microsoft's official
CUDA Plugin EP 0.1.0, with the host's CUDA 13 and cuDNN 9 libraries. The config
selected `runtime = "cuda"`, `device = "gpu"`, logical `device_id = 0`, and
`fallback = "error"`. Omaspeak registered the plugin, selected its published
`CUDAExecutionProvider` device, and attached that device to all four
Supertonic sessions through ORT's Plugin EP V2 API.

## Results

A fresh process using named speaker `F3` produced 648,272 mono 44.1 kHz PCM
samples, or 14.700 seconds of audio. Model loading took 699 ms, synthesis took
506 ms, and the whole process took 1.45 seconds. The WAV SHA-256 was
`29d687d2a08b3227e412442d9fa7853bed4a7aa2c5b7c5d1598644d1ba910514`.

A sustained run kept one engine loaded, completed two warmups, and measured 30
file-only syntheses. Each output contained 3.310 seconds of audio. Median
synthesis time was 47.627 ms, p95 was 48.082 ms, and median real-time factor
was 0.01439. During this exact run, `nvidia-smi dmon` recorded CUDA SM activity
of 3%, 54%, and 54% in consecutive samples.

The benchmark JSON records `effective_runtime = "cuda"` and
`fallback_used = false`. It intentionally leaves `placement_verified` false:
ORT may keep unsupported shape/control helpers on CPU, so Omaspeak does not
claim whole-graph GPU placement. Explicit Plugin EP device binding plus the
physical SM samples establish that the neural workload reached the GB10.

Changing the logical ordinal to `1` on this one-GPU host failed before
inference with `CUDA plugin device ordinal 1 is unavailable`; no WAV was
created. This also confirms that the configured value is a logical CUDA device
ordinal rather than ORT's unrelated hardware identifier.
