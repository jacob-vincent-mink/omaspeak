# NVIDIA GB10 CUDA validation — 2026-09-14

Omaspeak was built on `promaxgb10-d666` (Linux aarch64, NVIDIA GB10, CUDA
13.0.88, driver 580.173.02) against the strict pinned sherpa-onnx/ONNX Runtime
CUDA stack. All synthesis used `say --no-play` or `benchmark`, so audio was
written directly to WAV files without using speakers.

## Piper FP32

The run reported `effective_runtime="cuda"` and `fallback_used=false`. ONNX
Runtime recorded 23,338 CUDA provider node events and 8,120 CPU provider node
events. The latter are expected host-side or unsupported operations; the CUDA
events and GPU process telemetry establish accelerator placement.

| Runtime | Cold load | Hot p50 synthesis | Hot p50 RTF |
| --- | ---: | ---: | ---: |
| CUDA | 2,130 ms | 232.37 ms | 0.04491 |
| CPU | 583 ms | 313.18 ms | 0.05713 |

CUDA was 25.8% faster for hot synthesis and 3.65 times slower to initialize.
Seven files from each runtime were valid mono 16-bit PCM at 22.05 kHz. A
Moonshine transcription preserved the full sentence for both. Neither set
clipped; mean RMS was 0.094744 on CUDA and 0.094715 on CPU (about 0.03%
difference).

## Supertonic INT8

All four Supertonic component profiles contained CUDA events: 750, 1,278,
16,290, and 1,047 respectively. This exercises the patched per-component
provider routing as well as ordinary VITS/Piper routing.

| Runtime | Cold load | Hot p50 synthesis |
| --- | ---: | ---: |
| CUDA | 3,566 ms | 512.64 ms |
| CPU | 734 ms | 911.55 ms |

CUDA was 43.8% faster for hot synthesis. Independent Moonshine CPU ASR
produced identical transcripts for the CPU and CUDA WAVs. Duration differed by
0.018%, RMS by 1.18%, and neither output clipped.

Raw evidence on the validation host includes
`/tmp/omaspeak-{cuda,cpu}-benchmark.json`,
`/tmp/omaspeak-supertonic-{cuda,cpu}-benchmark.json`, ORT profile JSON files,
signal metrics, ASR comparison logs, and `nvidia-smi` samples.
