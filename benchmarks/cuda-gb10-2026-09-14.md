# Historical NVIDIA GB10 CUDA validation — 2026-09-14

This report covers the earlier ONNX Runtime 1.29 CUDA provider path. It is
retained as historical engineering evidence and does not validate the ORT 1.30
standalone CUDA Plugin EP release contract.

The former runtime-neutral Omaspeak executable was validated on
`promaxgb10-d666` (Linux aarch64, NVIDIA GB10, driver 580.173.02). The CUDA
runtime was a user-supplied ONNX Runtime 1.29.0 stack with its CUDA provider,
CUDA 13.0 vendor libraries, and cuDNN 9.26. Setup discovered and probed that
stack before applying it. No CUDA library is built into or linked by Omaspeak.

All synthesis used the file benchmark path. It wrote WAV files directly and
did not play audio.

## Runtime and placement

The setup preview reported `applied=false`, then the explicit apply reported
`applied=true`. Both probes found the CUDA provider, selected the GB10 GPU, and
reported the device accessible. Every CUDA synthesis reported
`effective_runtime="cuda"` and `fallback_used=false`.

Nsight Systems captured 84 CUDA kernel summary rows from the Omaspeak process.
They include ONNX Runtime CUDA dequantization, layer normalization, elementwise
operators, cuDNN convolution, and CUTLASS GEMM kernels. `nvidia-smi pmon`
independently observed Omaspeak using up to 35% SM and 636 MiB of framebuffer
memory. This establishes execution on the GPU rather than successful provider
registration alone.

## Cold and hot timing

Each cold row is a new process with one measured synthesis. Each hot row is a
new process with two warmups and ten measured syntheses of “The quick brown fox
jumps over the lazy dog.”

| Runtime | Model load | First synthesis | First result | Hot p50 | Hot p95 | Hot p50 RTF |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Default CPU | 431 ms | 551.21 ms | 982.21 ms | 760.13 ms | 764.78 ms | 0.23341 |
| CUDA GPU | 3,569 ms | 1,464.57 ms | 5,033.57 ms | 48.20 ms | 50.97 ms | 0.01480 |

CUDA initialization was 8.28 times slower. Once hot, CUDA synthesis was 15.77
times faster than default CPU in this run. The host was also serving SGLang,
so these figures document behavior under contention rather than an isolated
GB10 maximum.

## Output accuracy and voices

Independent Moonshine ASR transcribed the default CPU and CUDA voice-0 WAVs as
the exact nine-word input sentence, giving both outputs 0% WER. Both were valid
44.1 kHz mono WAVs without clipping. Their durations differed by 0.0146%; RMS
amplitude differed by 5.61%. Different PCM hashes are expected because the
Supertonic sampler is stochastic.

A separate CUDA synthesis selected voice 5 and produced a valid 5.563-second,
44.1 kHz mono WAV. This exercises speaker selection through the same CUDA
backend.

Commit `61ac63478e8e741fa84665d3d6cb9054a1d321d5` was rebuilt from origin
on the GB10 after the runtime-delivery stabilization and native-scaffolding
cleanup. The source tree was clean, with tree ID

SHA-256 was
`306123d74f85acb298b3f3d0b2654f2807746ee6c309863d0fdfc06c02ab1a4c`.

The complete eight-row inventory reported CUDA ordinal 0 as hardware ID 11794
(GPU), with ONNX Runtime 1.29.0 loaded, provider registration successful, and
both CUDA rows ready. Preview left the config SHA-256 unchanged at
`90f065e92c8e9ca33933be750ef95dddb68c0435d93bd5b2d885be90e73028d5`.

A direct no-play file benchmark performed one warmup and one measured
synthesis. It reported `effective_runtime=cuda` and `fallback_used=false`,
produced a valid 44.1 kHz mono PCM WAV, and synthesized 3.256 seconds of audio
in 48.97 ms (RTF 0.01504; 49.44 ms wall time). The earlier full placement proof
used the same inference path and observed Omaspeak with 518 MiB of GPU memory;
its Nsight Systems trace recorded ONNX Runtime CUDA kernels, cuDNN convolution,
and CUTLASS GEMM kernels. The exact `61ac634` smoke confirmed both existing
SGLang processes remained running with the same PIDs and allocations throughout.
